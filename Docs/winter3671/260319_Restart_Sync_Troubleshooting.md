# 🛠️ 트러블슈팅: 멀티플레이어 재시작(Restart) 동기화 버그 해결 (260319)

## 1. 이슈 개요 (Problem)
- **발생 상황**: 2인 협동 모드에서 '주문창(OrderDialogue)' 혹은 '결과창(Result)' 등 비전투 스테이지 진행 중, 어느 한 플레이어가 '다시하기'를 실행할 때 발생하는 동기화 불일치.
- **주요 증상**: 
  - 참가자(Client) 화면에서 재시작 후에도 이전 세션의 '확인창 UI'가 닫히지 않고 남음.
  - 플레이어가 '준비' 상태였던 데이터 잔상이 남아, 다음 판 시작 시 즉시 '준비 완료' 체크 표시가 튀는 현상.
  - 리셋 후 간헐적으로 마우스 커서와 화면 조작권이 돌아오지 않아 게임 진행 불가.

## 2. 근본 원인 분석 (Root Cause)
1. **Zero-Diff MetaState Issue**:
   - `OrderDialogue`(주문창) 상태에서 리셋하면 다시 `OrderDialogue`로 진입함.
   - Photon Fusion의 `OnChanged` 콜백은 **'값이 변하지 않았을 때(A->A)' 이벤트를 발생시키지 않음.** 이로 인해 참가자 단말은 리셋 신호를 감지하지 못함.
2. **네트워크 지연과 Race Condition**:
   - 방장이 데이터를 초기화해도, 참가자의 로컬 캐시에 남아있는 **Stale(오래된) 데이터**가 "아직 다른 사람이 투표 중이네?"라고 오판하여 UI를 다시 강제로 열어버리는 타이밍 이슈 확인.
3. **일시정지 상태(Pause)의 귀속**:
   - '다시하기' 과정에서 사용된 일시정지(`Pause`) 상태가 메타 상태 전이 시점에 명시적으로 해제되지 않아, 씬 이동 후에도 참가자의 조작권이 `Locked` 상태로 유지됨.

## 3. 해결 설계 및 구현 (Solution Design)
1. **전역 리셋 신호(Global Reset RPC) 도입**:
   - `MetaState` 감지에만 의존하지 않고, 방장이 '다시하기 최종 승인' 시점에 모든 클라이언트에게 **`RPC_GlobalFinalizeRestart`**를 전송하여 즉시 UI와 데이터를 강제 청소하도록 명령.
2. **권한 기반의 Authoritative Cleanup**:
   - 지연된 네트워크 데이터 문제를 방어하기 위해, 각 플레이어의 로컬 기기에서 **본인이 소유한 네트워크 변수(`IsReady`, `IsRestartVoting`)를 직접 초기화**하게 하여 데이터 오염 방지.
3. **강제 조작권 복구 (State Unlock)**:
   - `FinalizeRestart` 함수 내에서 `SetPauseInternal(false)`를 명시적으로 호출하고, `MetaState.OrderDialogue` 진입 시 모든 일시정지 관련 UI 레이어를 강제로 닫는 예외 처리 루틴 추가.

## 4. 최종 결과 (Result)
- **동결/잔상 이슈 100% 제거**: 
  - 주문창에서 주문창으로 다시 시작할 때 모든 플레이어의 UI가 0.1초 내외로 동기화되어 깨끗하게 갱신됨.
  - '준비' 표시 잔상이 사라져, 매 게임 시작 시 초기화된 상태로 쾌적한 플레이 가능.
- **UX 품질 향상**: 
  - 비전투 단계(주문/결과창)에서는 어두운 일시정지 화면 연출을 생략하고, 자연스럽게 현재 화면 위에 확인창만 띄움으로써 사용자 로딩 체감 단축.

## 5. 핵심 기술 스택
- **Unity 2022.3**
- **Photon Fusion 2 (Shared Mode)**: Multicast RPC, Authority Ownership, FixedUpdateNetwork Sync.
- **C#**: 이벤트 기반 UI 업데이트 및 상태 머신(FSM) 제어.
