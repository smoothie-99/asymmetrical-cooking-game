# 🥣 요리 채점 및 피드백 시스템 개발 가이드 (Winter3671)

본 문서는 요리 제출 기능 구현 전, 채점 로직과 피드백 시스템의 설계를 정리한 가이드입니다. 나중에 이 문서를 읽는 시점에서 즉시 작업을 재개할 수 있도록 핵심 정보를 담고 있습니다.

---

## 1. 프로젝트 현재 상황
- **기존 상태**: 요리 제출대가 없어 시간 초과(무조건 실패) 결과만 출력됨.
- **목표**: 쿠킹마스터로부터 받은 `DishRecord` 데이터를 정답지와 비교해 **점수(Score)**, **별(Stars)**, **피드백(Feedback)**을 생성하는 엔진 구축.

---

## 2. 요리 데이터 규격 (`DishRecord`)
쿠킹마스터로부터 다음의 계층 구조로 데이터가 전달됨.

### **[DishRecord]**
- `dishType`: 요리의 대분류 (예: "Salad", "SoupDish", "Steak")
- `ingredients`: `IngredientRecord`의 리스트 (그릇/재료가 담긴 **순서대로** 저장됨)

### **[IngredientRecord]**
- `itemType`: 재료 아이디 (예: "MandragoraItem", "BaconItem")
- `containerType`: 용기 타입 (Bowl, Plate 등. 용기 자체가 하나의 레코드가 됨)
- `contents`: 용기 내부에 담긴 재료들 (Recursive 구조)
- `cookState`: 조리 상태 (Raw, Cooked, Burned 등)
- `cookingSeq`: 조리 가공 순서 리스트 (**중요**)
  - 예: `["Washed", "Shredded", "Grilled"]`
- `cookingTime`: 해당 재료가 조리된 총 시간 (초 단위)
- `cutAngle`: 절단 각도 (도마질 결과)
- `flavor`: 조개 보석 색상 등에 따른 맛 정보 (예: "Green", "Red")

---

## 3. 조리 및 채점 규칙
### **조리 수단**
- **화구(Stove)**: 굽기/익히기
- **도마(Cutting Board)**: 썰기/절단
- **냄비(Pot)**: 끓이기
- **초록슬라임(Slime)**: 세척(Washing)

### **정답 판단 기준 (예시: 1번 손님)**
- **만드라고라**: 도마질 시 `채썰기(Shredded)`와 `잎 제거(LeafRemoved)` 중 **채썰기**만 정답으로 인정.
- **베이컨**: 화구에서 **30초 ~ 60초** 사이로 구워야 `Cooked` 상태로 판정. (60초 초과 시 `Burned`)
- **담는 순서**: 반드시 **만드라고라 → 베이컨** 순으로 접시에 담아야 함.

## 4. 12명의 손님(Level Design) 요약
| 순서 | 손님 | 주문 요리 | 핵심 요약 및 요구사항 |
| :--- | :--- | :--- | :--- |
| **01** | **상처 입은 용병** | 샐러드 | 고기 필수(Bacon), 뜨거운 것 금지(Raw), 동그란 것 금지(No Round) |
| 02 | 떠돌이 기사 | 스튜 | 고향 미신(풀 금지), 부드러운 목 넘김 |
| 03 | 견습 수녀 | 샐러드 | 살아있는 식재료 금지, 가벼운 식사 |
| 04 | 거지(왕) | 파스타 | 썰어 먹거나 끓인 국물 금지(구이형 고기?), 야채 포함 |
| 05 | 해적 | 스튜 | 신입의 실수 트라우마(비린내 금지), 뜨거운 국물 |
| 06 | 드래곤 | 스테이크 | 질긴 고기 금지, 불경한 재료 금지(우아한 플레이팅) |
| 07 | 마탑 마법사 | 꼬치구이 | 한 손 식사, 해산물 금지, 단 채소 금지 |
| 08 | 고블린 | 파이 | 달콤+매콤한 채소의 폭발적인 조화 |
| 09 | 오크 | 스테이크 | "고기! 고기! 풀은 싫다!" |
| 10 | 악마 | 파이 | 도마 위에서 발버둥 치는 녀석(살아있는 재료?) 포함 |
| 11 | 바위 골렘 | 꼬치구이 | 마법 깃든 재료들의 조화, 천천히 감상할 수 있는 형태 |
| 12 | 왕 | 파스타 | 이전과 같은 요리이나 '색다른 식재료'로 놀라게 할 것 |

---

## 5. 시스템 설계 가이드 (나중에 해야 할 일)

### **1) 데이터 관리 (ScriptableObjects)**
- **RecipeRequirementSO**: 스테이지별 정답 레시피 (기대하는 DishType, 순서, 재료 정보).
- **GuestDataSO**: 12명의 손님 데이터 (이미지, 성격, 피드백 문구 템플릿).

### **2) 채점 로직 (ScoringEngine)**
- `DishRecord`와 `RecipeRequirementSO`를 비교.
- 틀린 부분마다 감점 사유(Keyword)를 담은 `DeductionInfo` 리스트 생성.
- 가장 큰 감점 사유를 우선순위로 하여 손님의 말씨로 피드백 문장 구성.

### **3) 피드백 메세지 구성**
- 예: "식감은 좋군. 하지만 베이컨을 너무 오래 구워서 딱딱해!" (복합적인 피드백 생성 로직 적용)
